# PDF Report Specification

## 1. Goal

The PDF report should be suitable for internal engineering review, procurement discussion, and project documentation. It should not present itself as a certificate.

The report must be generated locally in the browser, preferably through `jsPDF` for consistency with the existing CAD AutoScript technology stack.

## 2. Report principles

- Show inputs and outputs together.
- Show assumptions and warnings clearly.
- Include visual layout and charts.
- Include dataset and calculation engine versions.
- Include an engineering disclaimer.
- Avoid hidden calculations.

## 3. Report file name

Suggested format:

```text
busbar-report_<project-or-tag>_<current>A_<voltage>V_<yyyy-mm-dd>_rev<rev>.pdf
```

Example:

```text
busbar-report_MCC-101_1600A_400V_2026-05-19_revA.pdf
```

## 4. Page structure

### Page 1: Summary

- title: Busbar Calculator Report;
- project metadata;
- overall status badge;
- selected profile summary;
- system type and electrical inputs;
- channel envelope dimensions;
- key warnings;
- generated timestamp and engine version.

### Page 2: Busbar layout

- rendered cross-section;
- phase arrangement;
- bar orientation;
- phase gaps;
- bar gaps;
- side/top clearances;
- minimum required clearance;
- channel envelope.

### Page 3: Thermal calculation

- material properties;
- resistance and losses;
- current density;
- cooling preset;
- ambient temperature;
- steady-state temperature;
- forecast chart;
- thermal warnings.

### Page 4: Short-circuit checks

- RMS short-circuit current;
- duration;
- peak current;
- thermal `I2t` result;
- required/actual area;
- electrodynamic force per meter;
- support spacing;
- bending stress utilization;
- short-circuit warnings.

### Page 5: Candidate comparison

- top candidate table;
- selected candidate highlight;
- alternative profile notes;
- mass/cost implications if available.

### Page 6: Calculation trace and references

- formulas/method IDs;
- dataset references and revisions;
- assumptions;
- limitation/disclaimer;
- change log for report revision.

## 5. Report object

```ts
export type PdfReportInput = {
  report: BusbarReport;
  options: PdfReportOptions;
  images: {
    layoutSvg?: string;
    temperatureChartPng?: string;
    shortCircuitDiagramSvg?: string;
  };
};

export type PdfReportOptions = {
  paperSize: 'A4' | 'Letter';
  orientation: 'portrait' | 'landscape';
  includeCalculationTrace: boolean;
  includeCandidateTable: boolean;
  includeWarnings: boolean;
  includeDisclaimer: boolean;
  language: 'en';
};
```

## 6. Visual hierarchy

Use clear report sections:

```text
1. Header
2. Status summary
3. Input table
4. Result table
5. Diagram/chart
6. Warnings
7. Notes and assumptions
```

Every page footer:

```text
CAD AutoScript Busbar Calculator | Engine vX.Y.Z | Dataset rev ... | Page N/M
```

## 8. Warnings section

Warnings should be printed with severity and recommended action:

```text
WARNING: AC_PROXIMITY_FACTOR_APPROXIMATED
The AC proximity correction factor for this multi-bar layout is approximate.
Recommended action: validate against IEC/vendor data or use a project-approved factor.
```

## 9. Disclaimer text

Suggested default:

> This report was generated by CAD AutoScript Busbar Calculator as an engineering aid. It does not replace licensed standards, manufacturer design verification, IEC 61439 assembly verification, short-circuit type tests, local electrical regulations, or review by a qualified electrical engineer. Values marked as estimated or example-only must not be used for final design release without validation.

## 10. Implementation outline

```ts
export async function buildPdfReport(input: PdfReportInput): Promise<Blob> {
  const doc = new jsPDF({
    orientation: input.options.orientation,
    unit: 'mm',
    format: input.options.paperSize.toLowerCase(),
  });

  drawSummaryPage(doc, input.report);
  drawLayoutPage(doc, input.report, input.images.layoutSvg);
  drawThermalPage(doc, input.report, input.images.temperatureChartPng);
  drawShortCircuitPage(doc, input.report, input.images.shortCircuitDiagramSvg);

  if (input.options.includeCandidateTable) {
    drawCandidatePage(doc, input.report);
  }

  if (input.options.includeCalculationTrace) {
    drawTracePage(doc, input.report);
  }

  return doc.output('blob');
}
```

## 11. PDF QA checklist

Before release:

- report opens in common PDF viewers;
- all pages have footers and page numbers;
- long project names wrap correctly;
- SVG/canvas images are sharp enough;
- warning text is readable;
- missing data is shown as `not evaluated`, not blank;
- generated file names are safe;
- report can be generated without internet access;
- report generated from a golden case is stable.

## 12. Future enhancements

- report template variants: compact, full, procurement, QA;
- digital signature block;

- revision comparison report;
